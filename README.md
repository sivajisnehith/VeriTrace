# VeriTrace

Face identification, web evidence discovery, and blockchain-anchored integrity verification.

VeriTrace takes a reference face image, runs a two-pass visual search across the public web using Google Lens, verifies and ranks prospective face matches using InsightFace (`buffalo_l`), extracts the strongest evidence, and notarizes a deterministic cryptographic fingerprint on Ethereum Sepolia.

## How It Works

### 1. Two-Pass Reverse Image Discovery
A single photo query often misses context or subject details. VeriTrace runs two parallel passes:
* **Pass 1 (Full Frame):** Searches the entire uploaded image to capture context, surroundings, and exact web scenes.
* **Pass 2 (Biometric Face Crop):** Isolates the bounding box of the highest-confidence face in the query image and searches the face alone. This finds the same person in different outfits, angles, and lighting.

Candidate URLs from both passes are merged and deduplicated.

### 2. Forensic Verification & Ranking
Each candidate image is downloaded, verified as a valid decodable image file, and processed with InsightFace:
* Candidate faces are detected and mapped to 512-dimensional normalized embeddings (ArcFace `w600k_r50`).
* Cosine similarity is computed against the query face embedding.
* The raw bytes of confirmed valid images are hashed using SHA-256.
* Candidates are ranked by descending similarity score.

### 3. Application Timestamp vs Blockchain Timestamp
VeriTrace separates two distinct timestamps:
* **`observed_at` (Application Event):** A UTC ISO-8601 timestamp generated by the backend when the evidence was observed/selected. This is included inside the canonical JSON payload before hashing. Two different searches observing the same web post at different times produce different fingerprints:
  `Fingerprint(Session A) != Fingerprint(Session B)`
  This allows multiple independent observation records for the same online post.
* **`block.timestamp` (Blockchain Consensus):** The immutable on-chain timestamp set by Ethereum validators when the transaction is mined into a block.

### 4. Canonical Representation & Tamper Detection
The evidence package consists of:
* `page_url`
* `title`
* `source`
* `image_sha256`
* `observed_at`

These fields are serialized into a deterministic canonical JSON string (keys sorted alphabetically, compact separators `","` and `":"`, UTF-8). 

The SHA-256 digest of this canonical string is registered on the smart contract. If anyone later alters the title, URL, image, or observation timestamp by even a single character, the recalculated fingerprint will not match the on-chain record, flagging the evidence as tampered.

## Smart Contract

* **Network:** Ethereum Sepolia (Chain ID: `11155111`)
* **Contract:** `VeriTraceRegistry`
* **Address:** `0xA86904bd58031564ED6431c519d0A633d9f15f14`
* **ABI File:** `contracts/VeriTraceRegistryABI.json`

The contract exposes two functions:
* `registerEvidence(bytes32 fingerprint)`: Records a new fingerprint with the block timestamp and caller address. Reverts if already registered.
* `verifyEvidence(bytes32 fingerprint)`: Returns `(bool exists, uint256 timestamp, address submitter)`.


Create a `.env` file in the root directory:


## API Reference

The VeriTrace backend exposes exactly three core pipeline endpoints:

### 1. `POST /api/web-search`
Uploads a reference face image, performs dual-pass Google Lens discovery, extracts candidate embeddings, computes face similarities, hashes candidate image bytes (SHA-256), and returns ranked candidates along with the `top_candidate`.

### 2. `POST /api/evidence/register`
Registers the selected evidence on Ethereum Sepolia. The backend generates the authoritative UTC `observed_at` timestamp and incorporates it into the canonical SHA-256 fingerprint.

* **Payload:**
  ```json
  {
    "page_url": "https://example.com/post",
    "title": "Article Title",
    "source": "example.com",
    "image_sha256": "1f80156a1c3c22c1bdeb52d5ea20055affd36dbf65e41fedfea72ef1fc1cded1"
  }
  ```

### 3. `POST /api/evidence/verify`
Audits evidence against Ethereum Sepolia. Supports Option A (direct `fingerprint`) or Option B (complete original fields: `page_url`, `title`, `source`, `image_sha256`, `observed_at`) to prove data integrity and detect tampering.
